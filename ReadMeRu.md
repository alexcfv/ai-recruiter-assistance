Инструмент для автоматизации рекрутинга. Система автоматизирует поиск кандидатов путем индексации PDF-резюме, глубокого анализа кода GitHub через протокол MCP (Machine Communication Protocol) и выполнения многоэтапного RAG-конвейера (Retrieval-Augmented Generation) для точного сопоставления кандидатов со сложными техническими требованиями.

## Ключевые технические особенности

- **Многоэтапный RAG-конвейер**: Сочетает семантический векторный поиск с переранжированием на базе LLM для достижения максимальной точности.
- **Глубокая интеграция с GitHub**: Использует MCP для анализа реальных примеров кода, структуры репозиториев и качества вклада разработчика, интегрируя эти данные напрямую в профессиональный профиль. Это позволяет системе сопоставлять заявленные в резюме навыки с реальным кодом.
- **Автоматический синтез профилей**: Генерирует структурированные JSON-профили из неструктурированных данных (PDF + GitHub), что позволяет выполнять сложные аналитические запросы.
- **Асинхронная архитектура**: Построена на `FastAPI` и `asyncio` для высокопроизводительной неблокирующей обработки данных.

## Как это работает

### 1. Индексация (`/index путь/к/резюме`)

> **Важно**: Когда вы запускаете инструмент в первый раз или добавили новые резюме, вы должны написать в чат с поиском кандидата команду `/index <путь_к_резюме>`, чтобы проиндексировать новые файлы.

- Сканирует папку на наличие файлов `.pdf`.
- Извлекает текст через `pdfplumber`, разбивает на чанки по 500 символов с перекрытием в 100 символов.
- Каждый чанк → эмбеддинг Mistral → сохраняется в ChromaDB (персистентная векторная БД).
- **Анализ GitHub (Новое):** Автоматически извлекает ссылки на GitHub, собирает данные о репозиториях (README, примеры кода) через **MCP (Machine Communication Protocol)** и выполняет сбалансированную оценку качества кода и технической глубины с помощью LLM.
- Для каждого нового резюме LLM строит структурированный профиль (резюме, навыки, опыт, проекты, образование, **github_analysis**) и сохраняет его в SQLite.
- Профили сохраняются между запусками и используются во время переранжирования (Этап B).

### 2. Процесс поиска

> **Важно**: Вы можете писать запросы на любом языке (русском, английском и др.), но **ответы с описанием кандидатов всегда будут на английском языке**. В аналитике же ответ будет на том языке на котором написан запрос.

```
Запрос пользователя → Валидация LLM → эмбеддинг → ChromaDB (топ чанков) → группировка по файлам → топ-10 кандидатов → получение профилей из SQLite → переранжирование LLM → final_score → объяснение топ-3
```

**Этап 0 — Валидация (Новое)**
- Запрос анализируется LLM, чтобы убедиться, что это корректный запрос на поиск кандидата.
- Приветствия, общие вопросы или нерелевантный текст отклоняются с вежливым объяснением.

**Этап A — Получение эмбеддингов**

- Запрос преобразуется в эмбеддинг Mistral.
- ChromaDB находит ближайшие чанки (по косинусному расстоянию).
- Чанки группируются по имени исходного файла для отбора **топ-10 кандидатов**.
- Для каждого файла: `embedding_score = 0.7 * best_chunk_distance + 0.3 * avg_chunk_distance`.
- **Чем ниже embedding_score, тем лучше совпадение** (расстояние ~0 = идентично, ~1.0 = не связано).

**Этап B — Переранжирование LLM через профили**
- Структурированные профили (включая анализ GitHub) для этих 10 кандидатов загружаются из SQLite.
- **Один** вызов LLM отправляет все 10 профилей + запрос и просит оценить каждого от 1 до 10.
- Итоговый балл сочетает векторное расстояние и оценку LLM:

`final_score = 0.3 * embedding_score + 0.7 * (1 - llm_rating / 10)`

- `embedding_score` обычно составляет ~0.2–0.8.
- `llm_rating` составляет 1–10 (10 = лучший).
- `(1 - llm_rating / 10)` инвертирует оценку LLM, чтобы оба слагаемых работали в одном направлении: **чем ниже, тем лучше**.
- Типичные итоговые баллы: ~0.15–0.6.

**Этап C — Объяснение**
- Для топ-3 кандидатов: LLM объясняет соответствие менее чем в 50 словах (навыки, компания, задачи) и отображает инсайты из GitHub.

### 3. Аналитика

> **Примечание**: Контекст и история сообщений в чате аналитики очищаются после обновления страницы.

```
Вопрос пользователя → получение всех профилей из SQLite → анализ LLM → ответ
```

- Система извлекает все структурированные JSON-профили из базы данных.
- Один вызов LLM обрабатывает весь набор данных, чтобы ответить на сложные аналитические вопросы (например, «Сколько кандидатов имеют степень PhD?», «Сравните кандидатов по уровню опыта»).

**Бюджет вызовов Mistral API:**

**При индексации (на 1 новое резюме):**
- **~5-10** вызовов эмбеддингов (зависит от длины резюме).
- **1** вызов анализа GitHub (если найдена ссылка).
- **1** вызов создания профиля. (создает профиль кандидата из резюме и записывает в SQLite)
- *Итого: ~7-12 вызовов на одно резюме.*

**При поиске (на 1 запрос):**
- **1** вызов валидации (проверка релевантности LLM).
- **1** вызов эмбеддинга (запрос → вектор).
- **1** вызов переранжирования (10 профилей + запрос → JSON оценки).
- **3** вызова объяснения (по одному на каждого топового кандидата).
- *Итого: **6** вызовов Mistral API на один поиск.*

**При аналитике (на 1 вопрос):**
- **1** вызов LLM (все профили + вопрос → ответ).
- *Итого: **1** вызов Mistral API на один аналитический вопрос.*

## Установка

### Запуск через Docker (Рекомендуется)

Самый простой способ запустить весь стек (Бэкенд, Фронтенд и Бот) — использовать Docker Compose.

1. **Настройка окружения:**
   Создайте файл `.env` в корневой директории и добавьте ваши ключи:
   ```bash
   MISTRAL_API_KEY=ваш_ключ
   GITHUB_TOKEN=ваш_токен_для_mcp
   ```

2. **Запуск:**
   ```bash
   docker-compose up --build
   ```

3. **Индексация резюме в Docker:**
   Поместите ваши резюме в папку `./data/resumes` в корне проекта. Она автоматически монтируется в `/app/data/resumes` внутри контейнера.
   При запуске индексации через интерфейс или бота указывайте путь: `/app/data/resumes`

### Локальная установка (для разработки)

```bash
git clone https://github.com/alexcfv/resume-rag-ranker.git
cd resume-rag-ranker
python -m venv venv
source venv/bin/activate
pip install -e .
# Создайте .env файл с ключами (см. выше)
python main.py

cd frontend
npm i
npm run dev
```

## Использование (API)

Система предоставляет REST API для взаимодействия с фронтендом. Основные эндпоинты:
- `POST /api/index` — индексировать PDF и создавать профили.
- `POST /api/search` — поиск кандидатов.
- `POST /api/analytics` — аналитические вопросы по базе кандидатов.

### Пример поискового запроса:

  ```text
  Стек технологий:
  Бэкенд (основной язык): Golang.
  Базы данных: PostgreSQL, Cassandra, ElasticSearch, Redis.
  Инфраструктура: Kafka, Kubernetes, Docker, gRPC.
  Опыт: Java, Python.
  ```
